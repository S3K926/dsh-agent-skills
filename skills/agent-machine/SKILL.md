# 动本机之前

## 改插件／客户端代码

- 改前**备份** ＋ 留一份**离线自检基线**（`node --check`、自带 selftest、沙盘测试）。
- 改后**三种证据分开验**：
  - **「装上了」** ＝ 装载路径（软链指向哪）＋ 源码 mtime 早于 apply 时间 ＋ 启动日志有 apply 行 —— **三样凑齐才算**；
  - **「能干活」** ＝ 功能面真跑一次（**离线全绿 ≠ 功能验收**）；
  - 配置文件里**该注册的地方都要对上**（依赖声明、bundle 列表、`node_modules` 软链、插件源），缺一处就是"找不到插件目录"。
- 宿主插件**改完要重启**才生效 —— 重启前说"已生效"都是假的。
- 客户端半边：**别在 factory 里碰 `document`**（加载期抛错会炸整页）。

## 改自写插件（2026-10-14 立）

- **改完顺手记一行 CHANGELOG**：`plugin-src/<插件>/CHANGELOG.md` —— 日期 ｜ 改了什么 ｜ 为什么 ｜ 怎么验的。
  **没记 = 没改完**（宿主插件改完要重启，不留痕过几天没人记得当时为什么这么改）。
- 自写的是哪三个：`dsh-auto-handoff`、`dsh-memory-board`、`dsh-selfwake`。
  ⚠ **别拿 `plugin-sources.json` 的"来源"字段判归属**（那一栏说的是安装方式，我拿它判错过两次）—— 去 GitHub 仓库和 README 认。
- ⚠ **注入标记两边要一起改**：`dsh-selfwake` 的标记表是 `dsh-auto-handoff` 那套"别把注入当成用户说的话"过滤器的唯一依据 —— 那边加了新标记，过滤这边要跟着补。
- **要推仓库 → 读技能 `dsh-plugin-publish`**：哪些仓库是我的、私密清单（本机 patch／路径／密钥／个人语境）、白名单推法、仓库描述别变问号、推完自查 —— 都在那一份里。**宁可不推，不可错推**。

## 设备命令

- 先确认通道（root／Shizuku／ADB **各自**授权），用 `id` 核实际身份，**别假设**是 uid=2000 或 root。
- 任何目录可读；**写**通常只允许普通 Download 目录（DCIM、Pictures、Android/data 这类只读）。
- **单条命令作为参数传**，别把用户给的文字拼成可执行 shell。
- **USER_REJECTED／确认超时就停**，不换通道重试。

## 真亏

- 只验「路由注册成功」就上线 → 漏了自激雪崩（没验"它会自己停"）。
- 拿 401/404 判路由在不在（鉴权在路由之前，判不了）。
- 在 pnpm 软链上整份复制目录会卡死。
- 改完没重启就说"已生效"。
